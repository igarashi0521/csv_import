# ハンズオン①:要件整理・設計(45分)

**ねらい**:AIに曖昧な依頼を整理させ、**確認事項と方針の選択は人が判断する**体験をする。

## 進め方

| 時間 | 内容 |
|---|---|
| 0:00-0:10 | 改修依頼書(`01_change_request.md`)を読み、自分で気になる点を3つ書き出す(AIは使わない) |
| 0:10-0:25 | AIに要件整理を依頼し、自分の書き出しと比較する |
| 0:25-0:40 | 曖昧な点について、実装方針の選択肢をAIに出させて比較する |
| 0:40-0:45 | 判断記録を書く |

## Step 1:自分で考える(AIなし)

依頼書を読んで、気になった点・確認したい点を3つ書いてください。

1.
2.
3.

> 先に自分の考えを持つことで、AIの出力を「評価できる」状態になります。

## Step 2:AIに要件整理を依頼する

`06_prompt_examples.md` の「指示」の例を参考に、次を依頼します。

- 依頼内容の整理(機能要件・非機能要件・制約)
- 曖昧な点・確認事項の洗い出し

**確認すること**

- [ ] 自分が挙げた点は、AIの出力に含まれていたか
- [ ] AIが挙げて、自分が気づかなかった点はあったか
- [ ] AIが勝手に仮定を置いていないか(置いている場合、その仮定は妥当か)

## Step 3:実装方針を比較する

ここでは **R2(重複 `order_id` の扱い)** を例に、AIに複数案を出させて比較します。

| 観点 | 案A | 案B | 案C |
|---|---|---|---|
| 概要 | | | |
| 変更範囲 | | | |
| リスク | | | |
| テストのしやすさ | | | |
| `Report.java` や運用への影響 | | | |

**比較の観点の例**:SQLの `INSERT OR REPLACE` / `ON CONFLICT DO UPDATE` / 事前SELECTで分岐、など。
`INSERT OR REPLACE` は「削除してから挿入」になる点など、**挙動の違いをAIの説明だけで鵜呑みにせず確認**してください。

## Step 4:判断記録

「AIに任せたこと」と「人が判断したこと」を分けて記録します。

| 論点 | AIが提案した内容 | 人が決めたこと | 決めた理由 |
|---|---|---|---|
| R1 文字コードの扱い | | | |
| R2 重複時の扱い | | | |
| R3 件数の数え方 | | | |
| R4 終了コード/通知 | | | |
