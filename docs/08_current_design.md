# 現行設計

この文書は、現在のソースコードとテストから確認できる受注CSV取込バッチの構造と動作をまとめたものです。改修後の仕様ではありません。

## 構成と責務

| クラス | 責務 |
|---|---|
| `Batch` | コマンドライン引数を処理し、CSV読み込み・行検証・DB登録・エラーログ出力を順に実行する |
| `CsvParser` | 指定された文字コードでCSVを読み、ヘッダー名と値を対応付けた行データにする。日付を `LocalDate` に変換する |
| `Validator` | 1行単位で必須項目、日付、数量、単価を検証し、エラーメッセージを返す |
| `Order` | 受注1件分の値を保持するrecord |
| `Repository` | SQLiteへの接続、`orders` テーブルの作成、受注の登録と月別取得を行う |
| `Config` | CSV文字コード、DB・エラーログの既定パス、数量上限を定義する |
| `Report` | DBに登録済みの受注を月別に集計して表示する |

## CSV取込の流れ

1. `Batch` がCSVファイルのパスと、任意のDB・エラーログのパスを受け取る。
2. `CsvParser` が設定済みのCP932（`windows-31j`）でファイルを読み込む。1行目をヘッダーとして扱い、空行は読み飛ばす。
3. 各データ行を `Validator` が検証する。
   - `order_id`、`customer_code`、`product_code` は空でないこと
   - `order_date` は実在する日付で、形式は `YYYY/MM/DD`
   - `quantity` は1以上、設定上限以下の整数（現在の上限は9999）
   - `unit_price` は0以上の整数
4. 検証エラーのある行は登録せず、行番号とエラー内容をUTF-8のエラーログに記録して次の行へ進む。
5. 正常行は空白を除去し、日付と数値を型変換して `Order` にし、`Repository` 経由でDBに登録する。
6. ファイルの処理終了後にトランザクションをコミットする。

`CsvParser` はダブルクォート内のカンマと `""` による引用符のエスケープを扱いますが、引用符内の改行には対応しません。ヘッダーは列名として使われ、必須ヘッダーの存在自体を事前検証する処理はありません。

## データ保存とトランザクション

DBには次の `orders` テーブルを使用します。

| 列 | 型 | 制約・内容 |
|---|---|---|
| `order_id` | TEXT | 主キー |
| `customer_code` | TEXT | NOT NULL |
| `order_date` | TEXT | NOT NULL、`YYYY-MM-DD` 形式 |
| `product_code` | TEXT | NOT NULL |
| `quantity` | INTEGER | NOT NULL |
| `unit_price` | INTEGER | NOT NULL |

登録SQLは通常の `INSERT` です。同じ `order_id` がDBに存在すると主キー制約違反になります。取込処理はファイル単位でトランザクションを開始し、正常終了時に一度だけコミットします。そのため、登録中にSQL例外などが起きてコミットに到達しない場合、その実行分はコミットされません。

DBとエラーログの既定名は、それぞれ `orders.db` と `import_errors.log` です。エラーログは取込開始時に作り直されます。

## 結果・終了コード

通常処理では、検証エラー行をスキップして残りの行を処理し、正常行をコミットします。現在、登録件数やエラー件数は画面に出力されません。検証エラーがあっても `Batch.run()` は終了コード0を返します。

引数が不足・不正な場合は使用方法を標準エラーに出して64を返します。ファイルI/OやDB登録などの例外は `main()` から処理されずに終了します。

## 月次レポート

`Report` は `Repository` を通じて指定月の受注を取得し、顧客別受注金額と曜日別件数を表示します。日付の保存形式を変える場合は、登録時だけでなく月別検索と日付読み戻しにも影響します。
